# C1 data protocol

The roadmap supplies the long-term layout and research questions. C1 covers foundation and data preparation. C2 covers baseline training and evaluation.

The public benchmark includes Japan, India, Norway, the United States, and China. The Czech Republic was excluded before baseline training. Bangladesh is the primary baseline domain. Local collection and annotation supply the route groups for C2. See the [Bangladesh collection protocol](bangladesh_collection.md).

- **Benchmark classes:** D00 (longitudinal crack), D10 (transverse crack), D20 (alligator crack), D40 (pothole), mapped to YOLO IDs 0–3 in that order. Default policy logs and excludes any other named class. Use `unknown: error` to inspect unexpected classes before deciding whether to include those images. An empty label means no retained benchmark boxes; it does not prove the image shows undamaged pavement.
- **Coordinates:** Work in the decoded image's stored pixel grid. Treat XML bounds as pixel edges, clip them to the image, and reject non-positive extents. For example, on a 100×50 image, (10, 10, 30, 30) maps to (0.2, 0.4, 0.2, 0.4). This pipeline applies no Pascal VOC one-based offset. Overlay raw and converted boxes on real images before freezing the convention; the XML format alone does not establish the coordinate origin.
- **Input checks:** Every labeled training image must have one XML of the same stem, and vice versa. Corrupt images, malformed annotations, inconsistent XML/image sizes and degenerate target boxes fail with the source paths; the dataset is staged before publication. Investigate such failures against the original archives before adopting any cleaning rule.
- **Split unit:** Separate train, validation and test within each country with target fractions 70/15/15 and seed 42. The default benchmark and Japan configs group consecutive sets of 100 lexicographically sorted filenames within each capture domain. The splitter uses the seed to order groups of equal size, assigns groups intact and treats ratios as targets. Filename adjacency is a proxy for capture sequence. Set `block_size: 1` to disable it, or supply route groups to merge images known to belong to the same route. It does not stratify classes. To supply route or sequence membership, set `groups` to a CSV with header `source_image,group`. Use the image paths relative to the configured raw root, with forward slashes. Provide a globally unique route ID per route and one row for each input image. Filename blocks, exact copies and known route groups are merged when they overlap and stay together, including across Chinese capture modes. An exact byte duplicate or route ID across countries stops the run for investigation.
- **Leakage limitation:** Hashing only detects byte-identical files. Without group metadata, nearby frames, re-encoded images and photos from the same route may cross splits. Do not describe that setting as route-disjoint. Country comparisons may also conflate geography with camera, collection protocol and class balance.

## Validation gate

1. Run the unit and integration tests. They cover count and geometry, invalid input, duplicate/group isolation, statistics, output hashes and repeatable split manifests.
2. Prepare and audit the official RDD2022 subsets for every country and capture domain included in C4. Confirm input membership against the release inventory and reconcile total source target boxes with label rows and per-class statistics. Review skipped classes and clipped boxes, and decide how to handle any anomalies before locking splits.
3. Visually overlay a small sample per country, including empty labels, border boxes and all four classes. Verify box alignment and review candidate near duplicates or shared routes. Record group metadata or document its absence.
4. Confirm all four classes occur overall and each country has retained boxes. Inspect support for each class by split; investigate missing classes and large ratio deviations before freezing the manifest. Regenerate into a fresh directory with the same inputs and compare manifest and statistics SHA-256. Preserve source release information, config, run log and final manifest for all future comparisons.

Complete this RDD2022 gate before public-domain comparisons. Freeze these data splits across model seeds; use validation to tune and reserve the project test split for final evaluation. Treat a run on an official sample as a compatibility check, not validation of the full benchmark.

## Bangladesh baseline protocol

Apply the Bangladesh readiness gate in the [C2 baseline guide](c2_baseline.md). Freeze the manifest and reserve about 20% of geographic route groups before creating development folds. In each development fold, training monitors its validation routes and selects `best.pt` by validation fitness. Tune settings on validation only. Once settings are frozen, use the fold test routes to report mean and sample standard deviation over the predefined fold and seed runs. Evaluate the final model only once on the reserved routes using its prespecified seed.

Record the code commit, data hashes, device and library versions. Report mAP at IoU 0.50 and across IoU 0.50–0.95. Ultralytics uses the maximum of its smoothed mean per-class F1 curve to select the confidence point for macro precision and recall. Report the harmonic mean of those two values as F1, plus AP50 and instance counts by class. See the [pinned metric implementation](https://github.com/ultralytics/ultralytics/blob/v8.3.160/ultralytics/utils/metrics.py).

Later, evaluate the frozen Bangladesh baseline on compatible public RDD2022 test data to measure transfer. Japan remains a comparison source for a separate Japan-to-Bangladesh experiment, with any Bangladesh fine-tuning restricted to development routes.
